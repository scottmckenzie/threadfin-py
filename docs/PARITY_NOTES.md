# Parity notes: Go Threadfin vs this port

Every ported behaviour is checked against golden files generated by running the
**real Go code** (`tools/go_golden/`). This page lists where the Go code does
something surprising, and whether the port copies it, fixes it or changes it.

Legend: **kept** = copied on purpose so goldens match, decide later if you want
it fixed. **fixed** = deliberately different. **new** = did not exist in Go.

## M3U parser (`src/threadfin/m3u.py`)

| # | Go behaviour | Status |
|---|---|---|
| 1 | Every apostrophe in the playlist became `"` *before* parsing, which corrupted names, groups, URLs and values containing one: `Joe's Pizza` became the name `Joe` with its `group-title` lost, `Children's TV` became `Children`, and `http://h/it's` became `http://h/it"s` (a broken stream URL). | **fixed**: apostrophes are plain text; single-quoted attributes (`tvg-id='x'`) still work. Go's corrupted output is kept in `tests/golden/m3u/apostrophes.golden.json` as documentation; correct output asserted in `tests/test_m3u_apostrophes.py` |
| 2 | `:-1` is deleted everywhere, including inside URLs (`host:-1/path` becomes `host/path`). | **kept** (harmless in practice) |
| 3 | The file is split on the text `#EXTINF` wherever it appears, so a name containing it breaks that entry. | **kept** |
| 4 | Channels without a name are *meant* to be skipped, but the Go code returned the partial entry, so they were emitted as blank-named channels (and re-saved that way in the local playlist copy). | **fixed**: skipped, and reported. `parse_m3u_report()` returns `skipped` entries with line number, reason (`no name`), URL and the original `#EXTINF` text. Entries with no URL, which Go dropped silently, are reported too (`no url`). A `tvg-name` still rescues an empty name, as in Go |
| 5 | Attribute-key pattern is `[a-zA-Z&=-]*`: digits and `_` are not allowed, so `tvg_id="x"` yields key `id`, and `tvg-id2="x"` yields key `""`. | **kept** |
| 6 | Only keys containing lowercase `tvg` are lowercased: `TVG-ID` stays as-is, so the channel gets a generated `threadfin-<md5>` id. | **kept** |
| 7 | Names keep leading whitespace (`, Channel 1` gives `" Channel 1"`); only trailing spaces are trimmed (not tabs). | **kept** |
| 8 | A whitespace-only line between `#EXTINF` and the URL becomes the URL. | **kept** |
| 10 | Names containing double quotes lost that text: `The "Best" Channel` became `The  Channel`, and a fully quoted name left the channel unnamed. Same root cause as #1: attributes were also looked for inside the name. | **fixed**: attributes are only read before the name, which starts at the first comma outside a quoted value (so `group-title="A, B"` still works); the name is taken verbatim. Go's output kept in `tests/golden/m3u/double_quotes_in_name.golden.json`; correct output in `tests/test_m3u_quoting.py` (incl. a randomized round-trip test) |
| 9 | Files over 10 MB use a second "optimized" parser that returns **zero channels for every input** (it filters out the `#EXTINF` line it then needs). | **fixed**: one parser for all sizes (test `test_large_playlist_is_parsed`) |

After the parser fixes, it was differential-tested against the real Go parser on 600 random
playlists (single-quoted attributes, CRLF, odd keys, empty names, commas, unicode, junk
lines): all 1,955 named streams were identical, and the 726 blank channels Go emitted were
exactly the entries this parser skips and reports. Fixtures where Go's output is known to be
wrong are listed in `INTENTIONAL_DIVERGENCES` in `tests/test_m3u_parser.py`, and a test
checks that each one still really differs.

Provider layer follow-through: `ParseResult.skipped` is carried into `RefreshResult.skipped` and
`StreamDatabase.skipped`, and the playlist copy escapes double quotes (see below).

## Settings (`src/threadfin/settings.py`)

| Go behaviour | Status |
|---|---|
| Defaults only fill *missing* keys; an explicit empty/zero value in the file wins (`uuid: ""` stays empty). | kept |
| On save: `backup.keep` 0 becomes 10, empty `backup.path` becomes the default, negative `buffer.timeout` becomes 0. | kept |
| JSON `null` decodes to the zero value of the field. | kept |
| `-port` / `-branch` command-line flags are written into `settings.json`, so they persist after the flag is removed. | kept |
| Unknown keys are dropped on save. | **changed**: preserved, so newer settings survive |
| Writes `settings.json` in place. | **changed**: atomic temp-file + rename |
| `buffer*`, `ffmpeg.options`, `vlc.*`, `storeBufferInRAM`, `ffmpeg.forceHttp` | kept in the file for compatibility, **inert** (no stream buffer in this port) |

## Channel probe (`src/threadfin/probe.py`, `probe_store.py`, `probe_service.py`)

| Go behaviour | Status |
|---|---|
| Frame rate is `round(num/den)` with halves away from zero (`5/2` gives 3, `-5/2` gives -3); unparsable parts default to 1; `x/0` gives 0. | kept |
| Last video stream and last audio stream win. | kept |
| Strict typing: a string/float `height` is an error. | kept |
| ffprobe errors were swallowed (`_`), so the UI showed blanks. | **fixed**: structured result with an error message |
| No timeout (a dead stream hangs the request forever). | **fixed**: 20 s default, process killed |
| ffprobe path = first `"ffmpeg"` substring replaced in the whole ffmpeg path. | **fixed**: sibling of the ffmpeg binary, then `PATH` |
| Any string was passed to ffprobe (`file:`, `concat:`, options). | **fixed**: URL scheme allow-list |
| Results were thrown away. | **new**: stored in SQLite (`data/probes.sqlite3`), history per URL, TTL cache (24 h ok / 5 min failed), shared in-flight probes, concurrency limit (default 1: providers cap connections per account) |

## Environment notes

* The upstream `vendor/` directory is incomplete (no `modules.txt`, missing
  `avfs`, `go-version`, `x/text`), so the Go app cannot be built from a plain
  clone. The golden scripts fetch modules from GitHub (`GOPROXY=direct`).
* This sandbox could not reach PyPI, so `pytest`, `ruff`, `mypy` and `fastapi`
  were not installable. Tests use `unittest` (also runs under pytest). Linting
  and type-checking have not been run yet.

## Stream filters (`src/threadfin/filters.py`)

Checked on 70 cases (incl. 40 randomised) against the real Go `createFilterRules` / `filterThisStream`.

| Go behaviour | Status |
|---|---|
| The first filter whose rule matches decides (exclude/include lists can only reject, never fall through to a later filter). | kept |
| `liveEvent` is the flag of the deciding filter, or of the last filter looked at when nothing matched. | kept |
| `{include}` / `!{exclude}` are cut out of the rule with the regexes `[{]+[^.]+[}]`; text with a `.` inside the braces is not recognised (`UK {a.b}` stays a plain rule that matches nothing); `!!{x}` and `{{x}}` mangle the condition. | kept |
| Condition lists: `", "` and `" ,"` are collapsed, an empty keyword (trailing comma) matches everything. | kept |
| Case-insensitive mode lowercases per character (Go `ToLower`), which differs from Python's `str.lower()` for `İ` and for final sigma. | kept (own `go_lower`) |
| Filters were visited in **random map order**, and as the first match decides, results and `liveEvent` could change between runs. | **fixed**: numeric key order |
| A `custom-filter` inherited the `liveEvent` flag of whichever filter was compiled before it (a reused variable). | **fixed**: custom filters are never live-event filters |
| Settings keys are matched case-insensitively and a wrong JSON type (a number for `filter`, a string for `caseSensitive`) aborts the whole build. | kept (as `FilterError`) |

## Providers (`src/threadfin/providers.py`, `streams_db.py`)

Download/refresh logic is tested against a local HTTP server; the stream database against the real
Go `buildDatabaseDVR` on 30 cases.

| Go behaviour | Status |
|---|---|
| Keys added to a new provider record (`name`, `tuner`=1, `file.threadfin`, `counter.*`, `provider.availability`=100 ...) fill only missing keys. | kept |
| Availability is `int(errors*100/downloads*-1 + 100)` (truncation: 1 error in 3 gives 66). | kept |
| A failed refresh keeps the old local copy and bumps `counter.error` and `counter.download`; a failed *new* provider is not kept. | kept |
| The local copy is a normalised playlist holding only `tvg-id`, `tvg-name`, `tvg-chno`, `tvg-logo`, `group-title`, name and URL, so custom filters only see those values. | kept |
| ...but a value containing `"` produced a broken line in that copy. | **fixed**: written with single quotes (both kinds: inner `"` becomes `'`) |
| gzip bodies are unpacked; corrupt or truncated gzip falls back to the raw bytes. | kept; **new**: size limit on the unpacked data |
| `Content-Disposition` without `=` panicked, and `filename="a.m3u"; size=3` became `a.m3u size`. | **fixed**: proper header parsing (also `filename*=`), path parts stripped |
| A malformed HDHomeRun lineup entry panicked. | **fixed**: skipped and reported |
| The last provider's error was the only one returned from a refresh-all or database build, so one bad provider's failure depended on random map order. | **fixed**: every provider's outcome is reported (`RefreshResult`, `StreamDatabase.errors`) and the rest still loads |
| The timeout covered the whole request; no size limit. | kept (total deadline, enforced even for slow trickling bodies); **new**: size limit |
| `strings.Contains(source, "http://")` decided between URL and file. | **changed**: the scheme must be http/https; local file sources can be switched off (`allow_local_files`) for the API layer |
| Group labels and values were sorted as two independent lists (a label could end up beside the wrong value, e.g. groups `a` and `a (1)`). | **fixed**: one list of `(name, count)` sorted by name |
| Providers were visited in random map order. | **changed**: settings order, M3U before HDHR |
| With no filters and at most 480 streams everything is active; above that everything is inactive plus a warning. Plex warning above 480 active. | kept |
| Loopback hosts bypass proxies. | kept |
